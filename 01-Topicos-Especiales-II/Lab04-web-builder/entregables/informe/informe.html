Introducción

Un Web Builder cambia el punto de partida del desarrollo: en lugar de abrir un editor y escribir, se describe en lenguaje natural la aplicación que se quiere, la herramienta genera el proyecto completo y se prueba desde una vista previa en el navegador. Este laboratorio propone recorrer ese flujo de punta a punta con una aplicación sencilla, un gestor de tareas de estudio, y pide algo más que obtener la app: probarla como usuario, pedir cambios de uno en uno, repetir las pruebas después de cada cambio y revisar el código que la herramienta produjo.

La guía propone estructurar toda instrucción en seis partes: objetivo, usuario, funciones, reglas, presentación y límites. La instrucción inicial que enviamos fue esta:

Construye una aplicación web llamada “Gestor de tareas de estudio”.

Usuario: estudiante universitario.

Debe permitir: crear, editar y eliminar tareas; asignar título, descripción, prioridad (Alta/Media/Baja), estado (Pendiente/En progreso/Terminada) y fecha límite; buscar por texto y filtrar por estado y prioridad.

Reglas: no permitir guardar una tarea sin título; mostrar mensajes claros cuando falten datos; conservar las tareas en el navegador mediante almacenamiento local; no usar servicios externos ni autenticación.

Interfaz: sencilla, responsive, con una lista o tablero claro y un formulario fácil de usar.

Genera una primera versión funcional. No agregues funciones distintas a las solicitadas.

Dejamos que la herramienta terminara sin interrumpirla y abrimos la vista previa sin pedir cambios, para tener una línea base. [PENDIENTE: cuánto tardó, qué pasos mostró el panel izquierdo, y si la primera versión salió completa o con faltantes]
